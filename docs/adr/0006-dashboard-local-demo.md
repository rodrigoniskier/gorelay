# ADR 0006 — Local dashboard and isolated failure simulator

Status: implementation proposal, human review pending.

## Contract and invariants

The dashboard is English, embedded HTML/CSS/JavaScript served by Go at `/dashboard/`, with no remote assets. PostgreSQL remains the source of truth. A repeatable-read read-only snapshot returns totals and the latest 100 events. Success is delivered / (delivered + dead_letter); pending, retry and generic processed are excluded, and a zero denominator is unavailable, not zero percent. Recorded successful attempt duration measures claim-to-confirm time, not HTTP wire latency. Active and expired leases describe persisted work, not process heartbeats. Details omit payloads, idempotency keys, lease tokens and transport errors.

No migration or delivery-state change is needed. Existing bounded retries, persisted slots and fencing remain authoritative. At-least-once redelivery can duplicate accepted requests; finite attempt budgets do not guarantee any successful receipt. Consumers must deduplicate the stable delivery ID. Dead-letter events are retained and never automatically re-driven.

## Demo isolation

`GORELAY_DASHBOARD_DEMO=1` explicitly enables administrative controls and an in-process HTTP recipient on an ephemeral literal loopback port. Workers still require `GORELAY_WORKERS` > 0; demo startup fails otherwise. The sole synthetic destination is `dashboard-demo`; the recipient endpoint and bearer capability are generated by the server, never supplied by a browser. No arbitrary target URL is accepted. The existing HTTPProcessor has proxies and redirects disabled and enforces loopback dialing, request timeout and lease budget.

The recipient supports 200, 429 (Retry-After 1 second), 503 and waiting for request cancellation. Its capability protects mode effects from unrelated local POSTs. The recipient never logs or stores payloads. The dashboard controls require exact same-origin Origin, same-origin browser fetch metadata when supplied, JSON, and a random per-process CSRF token. Host and peer must be loopback. Read access rejects foreign origins and cross-site fetches. Existing /v1 contracts retain their original origin restriction.

Generation is atomic, synthetic only, 1..100 events per operation, serialized per process and rate-limited to one batch per 5 seconds. No partial batch is committed. This is a local demo limit, not a distributed production quota. Existing real events remain visible; use a separate database for a clean demonstration. Polling is 3 seconds, serialized, paused while hidden, with timeout and visible errors.

## Limits

Read queries aggregate all rows every poll: suitable for a local demonstration, not a production analytics service. Latest 100 rows and latest 100 attempts are explicit bounds. No authentication for other local users, no production deployment, no worker heartbeat inventory, no manual DLQ re-drive. Recipient state and CSRF token reset on restart; SQL events and retries survive. Multiple application instances have independent control state and rate limits. Stop old binaries before schema upgrades.
